Resumen

TerritoryOS te permite:

  • Administrar territorios (crear, buscar, seleccionar).
  • Registrar asignaciones por territorio (conductor, fecha, estado, notas).
  • Ver analíticas sobre estado general y actividad.
  • Crear un programa semanal (Semana anterior / actual / siguiente).
  • Sincronizar salidas del programa hacia el historial de cada territorio.
  • Imprimir programa como PDF, con plantilla de imagen o color.

Cómo guarda los datos

Todo se guarda en el navegador (localStorage). No requiere internet para funcionar.

Para quién está pensado

Para uso personal o de una sola persona. Si querés multiusuario/login, hay que agregar backend.

Impresión

Se abre una ventana de impresión y podés guardar como PDF desde el navegador.

Primeros pasos

Abrir la app

  • Abrí el archivo index.html en tu navegador (Chrome/Edge recomendado).
  • Si está en GitHub Pages, entrás por la URL pública del sitio.

Navegación

El menú lateral permite ir a: Programa, Dashboard, Territorios, Analíticas, etc. Si ves dos opciones “activas” al mismo tiempo, revisá que cada botón tenga su data-nav correcto.

Recomendado

  • Usá Ctrl + F5 si actualizaste el archivo y no ves cambios.
  • Si algo “deja de funcionar”, abrí la consola: F12 → Console.

Territorios

En la sección Territorios podés crear y seleccionar un territorio para gestionar su historial.

Crear un territorio

  • Click en Nuevo territorio.
  • Completá el nombre/número según tu formato (ej: “Territorio 01”).
  • Guardá.

Buscar un territorio

  • Usá el buscador superior para filtrar por nombre o número.

Registros por territorio

Cada territorio tiene un Historial de registros. Cada registro suele incluir:

  • Conductor (quién lo llevó).
  • Fecha de asignación.
  • Estado (ej: En progreso / Completado, según tu implementación).
  • Notas u observaciones (si tu versión lo incluye).

Agregar un registro

  • Seleccioná el territorio.
  • En el panel “Nueva asignación”, completá los campos.
  • Click en Confirmar registro.

Editar un registro

  • En el historial, abrí el menú de acciones (tres puntitos).
  • Elegí Editar registro y guardá cambios.

Si el menú de acciones se ve cortado

Esto suele pasar por un contenedor con overflow-x-auto o overflow:hidden. Solución típica: agregar overflow-y-visible y un z-index más alto al card del historial.

Analíticas

En Analíticas

  • Total de territorios con actividad
  • Distribución por estado
  • Registros recientes (según tu vista)

Las analíticas dependen de lo que tu versión compute (puede variar si agregaste/quitaste gráficos).

Programa semanal

El Programa semanal está pensado para cargar salidas y luego, si querés, sincronizarlas con los territorios. Maneja 3 semanas: Semana anterior, Semana actual y Semana siguiente.

Agregar una salida

  • Elegí la semana (anterior/actual/siguiente).
  • Click en Agregar salida para crear una fila.
  • Completá: Día, Fecha, Hora, Lugar, Territorios, Conduce, Tipo.

Campo “Territorios”

  • Formato sugerido: “10 y 11” o “4-50-56”.
  • SN: salida sin territorio (no sincroniza a territorios).

Tipo: Normal / Asamblea / Conmemoración

  • Normal: sincroniza a territorios (si hay territorios válidos).
  • Asamblea y Conmemoración: se imprimen como evento especial y no sincronizan.

Si al elegir “Asamblea” imprimir deja de responder, suele ser por un error JS (por ejemplo usar una variable antes de declararla). Revisá la consola con F12.

Sincronizar programa → territorios

El botón Sincronizar toma salidas del programa (de la semana seleccionada) y crea registros en los territorios correspondientes.

Reglas de sincronización

  • Solo sincroniza filas con Tipo = Normal.
  • Si el campo Territorios es SN, se ignora (no genera registros).
  • Si hay múltiples territorios (ej: “10 y 11”), crea registro en ambos.
  • Usa la Fecha y el Conductor del programa como datos del registro en el territorio.

Recomendación

Antes de sincronizar, asegurate de que todas las filas tengan fecha y conductor. Si falta alguno, puede quedar un registro “incompleto”.

Imprimir programa

Desde Programa semanal podés imprimir/guardar como PDF el programa de la semana seleccionada.

Plantilla: imagen o color

  • Podés subir una imagen para que salga como encabezado/banda superior.
  • Si no subís imagen, el encabezado se imprime con un color.

Guardado de imagen (RAM vs localStorage)

  • Si la imagen es pequeña (por ejemplo <= 300 KB), se puede guardar en localStorage y queda aunque recargues la página.
  • Si es grande, se usa en RAM (solo sesión). Si recargás, se pierde.

Tips para que salga el fondo/colores

  • En Chrome/Edge: cuando imprimís, activá la opción “Gráficos de fondo” si querés que salga el color de fondo.
  • Para evitar depender de esa opción, se recomienda imprimir un banner con <img> (si existe).

Varias páginas

Si hay muchas filas, el PDF sale en varias páginas. Para que el encabezado de la tabla se repita, se usa: 

thead { display: table-header-group; }
tr { page-break-inside: avoid; }

Mapa (Google My Maps / iframe)

Se puede incrustar un mapa usando un <iframe> de Google My Maps.

Limitación importante

El menú/barra dentro del iframe es de Google y no puede “sacarse” con CSS desde tu página (por seguridad del navegador). Lo que sí podés hacer: aumentar la altura del iframe o mostrar un botón “Abrir mapa”.

Datos y límites

¿Cuánto ocupa?

Como regla general, un registro típico (conductor, fecha, estado, notas) suele ocupar pocos KB. 50 territorios x 5 registros = 250 registros: normalmente menos de 1 MB. Lo que más ocupa son imágenes en localStorage (por eso se limita a ~300KB).

Limitaciones del localStorage

  • El navegador tiene un límite (varía, pero suele ser ~5MB por dominio/origen).
  • Guardar imágenes grandes lo llena rápido.
  • Si se llena, el navegador puede lanzar errores al guardar.

Ventajas de “todo en un solo index.html”

  • Fácil de llevar, copiar y subir.
  • No requiere backend.
  • Funciona offline.

Desventajas

  • Login/multiusuario requiere un servidor.
  • Los datos están atados al navegador/dispositivo (si cambiás de PC, no se migran solos).
  • Riesgo de perder datos si se borra el storage del navegador.

Backup / exportación

Recomendación: hacer un backup periódico.

Opción simple

  • Guardar una copia del archivo index.html en otro lugar.
  • Exportar/pegar los datos si tu versión tiene botones “Export/Import”.

Idea recomendada (si querés agregarlo)

Agregar 2 botones: Exportar datos (descarga JSON) y Importar datos (carga JSON). Esto te permite migrar de PC sin depender del navegador.

Solución de problemas

“No responde nada / se rompió la página”

  • Abrí F12 → Console y mirá errores rojos.
  • Errores típicos:
    • Unexpected end of input / Unterminated template literal: suele ser un backtick ` sin cerrar o HTML mal copiado.
    • Si en un string HTML usás </script>, dentro del template literal debe ser <\/script>.

“Imprimir no hace nada”

  • Revisá consola: muchas veces se rompe dentro de printSchedule().
  • Causa común: usar una variable antes de definirla (ej: dateShort).
  • Otra causa: el popup está bloqueado. Permití popups para el sitio.

“El menú de acciones se corta”

  • Revisá contenedores con overflow en el historial.
  • Solución típica: overflow-y-visible y subir z-index del card.

“No se guardan datos al recargar”

  • Confirmá que tu versión llama a save... después de cambios (ej: en updateScheduleField).
  • Confirmá que no estás usando solo variables RAM para todo.
  • Confirmá que no está lleno el storage (errores de quota).

FAQ

¿Se puede usar login?

Sí, pero no con solo HTML. Requiere backend (Firebase, Supabase, servidor propio, etc.).

¿Se puede sincronizar con Google My Maps “por territorio”?

Con iframe solo se puede mostrar el mapa general. Para “control por territorios” hay que usar una API o un enfoque más avanzado.

¿Qué pasa si cambio de PC?

El storage del navegador no viaja con vos. Para migrar necesitás exportar datos o copiar el storage manualmente (no recomendable).

¿Se puede usar con varias personas?

Se puede, pero si cada uno abre la app en su navegador, cada uno tendrá “su copia” de datos. Multiusuario real requiere backend.
